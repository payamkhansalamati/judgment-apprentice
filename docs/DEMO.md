# Demo recording guide

Use a new **simulated** session and synthetic data. The app must keep its simulated label visible. This document prepares an actual recording; no footage exists or is generated by the implementation.

## 60-second storyboard

| Time | On screen | Presenter narration / action |
| --- | --- | --- |
| 0–8 s | Overview, then expert workspace | “All tests passed. So why did the expert stop the release? Judgment Apprentice captures the judgment behind the click.” Start a fresh simulated session and grant consent. |
| 8–20 s | Case B and companion | Point to release 2.4.1 and test report 2.4.0. Save Hold. Show the version question, then the counterfactual: “If the versions matched, would you approve?” Use the visibly scripted expert answer. |
| 20–31 s | Debrief / correction | Explain that green tests alone are insufficient. Correct the coverage rule to “Only if the tests cover the changed functionality.” Answer the remaining gaps. |
| 31–40 s | Teach-back and map | “Observed is not yet trusted. The expert confirms the evidence-linked map.” Explicitly confirm the current version. Show a clickable evidence artifact. |
| 40–52 s | Approved practice challenge | Approve the template. Predict Ready for approval on the unseen older-report case. Show the blocked save and recorded first answer. Correct to Hold. |
| 52–60 s | Results / knowledge boundaries | Complete the independent assessment if prerecorded transitions allow. Show corrected versus independent results. “Teach with verified evidence, and escalate what remains unresolved.” |

For a strict one-take 60-second cut, prefill debrief fields before recording without submitting them, and use a separate prepared session for the final Results view. Do not imply that prerecorded/prepared transitions are a continuous live capture or that simulated speech is a provider conversation.

## Full demonstration script

### 1. Start and establish consent

Create a fresh simulated session. Read the simulated label aloud. Explain that all rules are fictional company policies and the review data is synthetic. Grant app consent. If showing real browser sharing, use the explicit share button and choose only the synthetic sandbox. Apply a configured mask if needed. Point to the capture indicator.

Demonstrate Pause/Let me finish. In-app activity should delay a queued question; silence alone must not be described as proof that the reviewer has finished reading. Use Ask now to request the next relevant question. Typed answers are the accessible path for this demo.

### 2. Ground three questions in the expert cases

- **Case A:** release and report versions match, tests cover discount calculation, and the reviewer differs from the author. Save Ready for approval with a justification. Explain why this is the straightforward case.
- **Case B:** tests passed, but report 2.4.0 does not match release 2.4.1. Attempt Ready for approval if desired, show the policy violation, then save Hold. Ask why version mismatch blocks the release and record the scripted answer.
- **Counterfactual / Case C:** ask, “If the versions matched, would you approve? What else must be true?” Case C has matching versions but tests only login rather than the changed discount calculation. Record the scripted coverage answer, then refine its wording during debrief so the correction and confirmation boundaries remain visible.
- **Guardrail:** ask who may independently review the change and whether the author can do it. Record that the reviewer must be a different person.

Show the observation timeline. Distinguish a stored sandbox decision from a simulated screen observation and an expert answer. Do not claim that this app can read arbitrary external typing events.

### 3. Debrief, correct, and confirm

Start debrief. Show that these are three previously unanswered questions:

1. Are there exceptions to these checks?
2. Who owns escalation when evidence is ambiguous?
3. What should a newcomer do when required information is missing?

Show that Review teach-back remains disabled while required gaps are unanswered; the server also rejects an incomplete teach-back. Fill each answer using the visibly scripted demo option or manually quote your own chosen expert response. Corrections must contain real typed/scripted stored evidence; never describe a fabricated quotation as expert speech.

Correct the coverage rule to: **“Only if the tests cover the changed functionality.”** Read the teach-back. Show observed versus expert-confirmed status and explicitly confirm the current version. Open a rule and inspect its evidence link. Demonstrate that refreshing retains the approved map.

For the reconfirmation behavior, edit a confirmed rule, show the incremented draft version and invalidated challenges, then read teach-back and explicitly confirm again. Explain that prior confirmation does not carry forward to edited knowledge.

### 4. Approve controlled challenges and catch an unsafe learner answer

Show the two unseen challenge templates. Their expected decisions come from supported deterministic policies. Explicitly approve both as the expert before assessment.

In the Search ranking practice case, submit **Ready for approval** with “The tests passed.” The first answer must remain recorded and the case decision must not save. Show the version-mismatch explanation. Request a hint only after the first answer; open the confirmed evidence. Submit **Hold** with “The test report version does not match the software version.” Show the assisted outcome: hinted when a hint was used, corrected when the learner revised without a hint.

In the Refund calculation assessment, inspect version 4.0, missing refund coverage, and identical author/reviewer. Explain that tutor hints are reduced. Submit **Hold** with “Tests do not cover the changed refund functionality, and the reviewer is the same person as the author.” Explain that a small English concept rubric checks for the exercised coverage and reviewer-independence concepts; it does not establish general explanation quality or competence.

### 5. Results, boundaries, and privacy

Open Results. Explain independent versus hinted/corrected success, and practice areas supported by attempted checks. Do not invent a mastery percentage.

Mention that ambiguous exceptions require escalation to the release owner. Use off-record and verify active sharing and voice stop. Explain that mute has a narrower scope and already transmitted provider requests cannot be recalled. Use the open session’s Delete session control, confirm deletion, and show its old evidence references no longer resolve. External provider retention is governed separately.

### Optional live segment

Only after completing [live setup](LIVE_SETUP.md), record a separate explicitly live session. Show microphone permission, signed-URL connection, actual transcript events, a real structured visual observation, and three live screen-grounded questions. Do not present a mocked test or simulated storyboard as evidence that these live steps were exercised.
